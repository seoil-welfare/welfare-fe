# 커밋 메시지 규칙

형식이 맞지 않으면 커밋이 취소돼요. `npm install`을 한 번 하면 검사가 자동으로 켜집니다.

## 형식

```
<타입>: <무엇을 했는지>

<필요하면 한 줄 띄우고 이유나 자세한 내용>
```

```
feat: 홈 상단 바로가기 카드 추가
fix: 소식 날짜 머리글 여백 어긋남 수정
style: 상단바 그림자 제거
```

## 타입

| 타입 | 언제 쓰나 | 예시 |
|---|---|---|
| `feat` | 새 기능이나 화면 | `feat: 이용자 등록 화면 추가` |
| `fix` | 버그 수정 | `fix: 일지 저장 후 목록이 갱신되지 않는 문제 수정` |
| `style` | 화면 모양만 바꿈 (색, 간격, 레이아웃) | `style: 홈 카드 간격 조정` |
| `refactor` | 동작은 같고 코드 구조만 바꿈 | `refactor: 목록 행을 ListRow로 통일` |
| `docs` | 문서 | `docs: README 실행 경로 수정` |
| `chore` | 설정, 패키지, 빌드, 목 데이터 | `chore: 의존성 업데이트` |
| `test` | 검사 스크립트 추가·수정 | `test: 달력 작성 버튼 노출 검사 추가` |

`style`은 코드 포맷팅이 아니라 **화면 모양 변경**에 씁니다. 이 프로젝트는 UI 작업이 대부분이라 이렇게 나눕니다.

## 규칙

- 타입은 위 7개 중 하나, 소문자로 씁니다.
- 콜론(`:`) 뒤에 한 칸 띄웁니다.
- 설명은 한국어로 50자 이내, 끝에 마침표를 붙이지 않습니다.
- 한 커밋에는 한 가지 일만 담습니다. "A 수정, B 추가"처럼 쓰게 되면 커밋을 나눕니다.
- 범위를 밝히고 싶으면 타입 뒤 괄호에 영어 소문자로 씁니다. 예: `fix(calendar): 주말 표시 오류 수정`

## 검사 통과 예외

git이 자동으로 만드는 메시지는 검사하지 않습니다: `Merge ...`, `Revert ...`, `fixup! ...`, `squash! ...`

## 검사가 동작하는 방식

- `.githooks/commit-msg`가 커밋할 때마다 `scripts/check-commit-msg.mjs`를 실행합니다.
- `npm install`(또는 `npm ci`) 때 `package.json`의 `prepare` 스크립트가 `git config core.hooksPath .githooks`를 설정합니다.
- 이미 설치를 마친 사람은 `npm install`을 한 번 더 하거나 위 `git config` 명령을 직접 실행하면 됩니다.
- 메시지를 미리 확인하려면: `node scripts/check-commit-msg.mjs --message "feat: 홈 화면 추가"`
- `git commit --no-verify`로 검사를 건너뛸 수는 있지만 쓰지 않습니다.
